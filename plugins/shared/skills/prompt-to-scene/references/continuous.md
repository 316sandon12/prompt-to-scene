# Continuous creation contracts

- `art_directions` lists forest_apothecary, wasteland_workshop and orbital_workshop. `compare_art_directions` makes cached real geometry studio drafts. Read their actual PNGs via workbench studio images. `select_art_direction` remembers the explicit choice and optional theme palette; `create_art_kit` uses this direction for structural geometry, matching icons and UI. These are authored sets, not arbitrary AI assets. Use custom scripts for other requirements and review the actual game camera.
- `creation_dependencies` returns exact model/icon/item/screen links. `plan_creation_update` takes a named part and validated changes. `update_creation(update_id)` applies only these dependencies; `undo=true` restores that update when nothing newer has superseded it. Manual icon artwork can be retained with refresh_icons=false. Stable native item references propagate to screens without recreating layouts. Respect part locks and version conflicts.
- `inspect_project_system` reads the selected native components/actors; `prepare_project_adapter` creates a mapping. Unity can generate a typed forwarding component for public quantity, float health/max-health and atomic commit APIs. Never guess transaction semantics or private fields. `install_project_adapter` waits for compilation then binds. Existing compatible interfaces need no code generation. UE uses BPI_PTSProjectAdapter; `create_adapter_starter` creates an editable native Blueprint example with transactions disabled until adapted. It does not automatically rewrite arbitrary Blueprint graphs. Resolve genuinely missing APIs with the user/project code, then rescan and bind. External save ownership stays with the game.
- `attach_gameplay` attaches an existing flow to the current scene and binds matching present objects/UI. Unity shares state in memory within the running game. UE persist_on_travel writes bridge progress on level transition; this is separate from per-rule autosave. Bind external providers per scene as needed.
- `configure_gameplay` accepts save_version (positive integer), item_aliases and rule_aliases (lists of {from_id,to_id}). Increase save_version when changing aliases; old IDs must be obsolete and target existing distinct IDs. Keep cumulative aliases for supported old saves. Quantities/completed flags migrate; a future version, invalid save or stack overflow must not be overwritten. Unity keeps .bak; UE retains a before-version slot. These migrations do not rewrite a third-party save format.
- `delivery_context` reports actual native engine/scenes. `build_game` produces the host platform player from saved scenes, with the installed SDK. It preserves build settings and records actual output; a build receipt is not proof of gameplay. When running the game is within the request, `launch_game` starts that exact retained build (and the chosen UE map). The normal game window closes it. `cleanup_delivery` removes only completed-task logs/staging and keeps the player and source. Do not delete external saves, unrelated caches or engine dependencies. Native Mac verification does not certify Windows engine execution or older UE template compatibility.
