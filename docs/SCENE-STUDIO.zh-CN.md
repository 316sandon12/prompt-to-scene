# 选位置、试放，再采用

这组功能位于 v0.15 开发分支，正式 v0.14 下载包尚不包含。源码运行后重新连接项目，更新 Unity／UE 桥接；Unity 等待编译，UE 重启编辑器。

## 从哪里开始

1. 在 Unity／UE 选中一个柜台、地面物体或占位模型，退出 Play 模式。
2. 在创作画布展开「场景适配」，点 **参考这里制作**。插件保存目标尺寸、周围对象、材质参数和实际游戏镜头截图。没有可用相机时会提示选择相机；不会用名字猜画面。
3. 描述要制作的东西。模型与图片沿用同一份参考；生成仍由当前 AI 客户端的建模／图片工具，或已配置的服务完成。
4. 从展廊打开生成结果，在 **放进游戏里看看 → 预览当前作品** 查看效果。满意后点「采用」，需要恢复时点「撤销」。

例如：

> 在选中的柜台上制作一个药箱，配色参考当前商店。把手要从玩家视角看得清。再制作配套的透明背包图标，以 64×64 显示，四周留 10% 空白。

## 模型试放与修改

- **放在目标表面**：根据实测包围盒对齐底面和中心。目标应是实际承托面；它不判断复杂网格的凹槽或曲面。
- **放进占位范围**：用于占位模型。勾选「替换占位物」后，预览隐藏占位物；采用后停用／隐藏占位物并停用其碰撞，撤销会恢复。
- **缩小试放**：只做等比缩小；保留源文件，不改变模型比例。缩放锁、部件几何锁、用途尺寸下限会阻止不合适的调整。
- **只改一个部件的材质**：选择部件，只改颜色或粗糙度。其他部件和锁定继续保留。修改形成新版本，可恢复修改前版本；若之后另有修改，会要求到历史记录选择版本。

模型预览使用临时静态几何，不在副本上运行用户脚本。截图后移除副本，恢复原物体的显示。前后图使用同一相机；采用时再次核对源版本、对象姿态、相机与碰撞范围。后续手工改动源物体后，撤销会拒绝覆盖它。

碰撞预检针对已读取的可见几何中启用碰撞的对象；无碰撞的天空球不会挡住放置，纯碰撞体和导航数据不在这次预检范围内。视觉遮挡、复杂曲面、门的运动轨迹仍应在游戏中看。当前试放支持直立静态模型，不支持骨骼动画、运行时角色相机或任意俯仰姿态。

## 图片和 UI 预览

预览提供三张图：

- 按指定像素尺寸和位置叠到场景参考上，保持原比例与透明度。
- 在项目背景色上比较 32、64、128 像素的轮廓。
- 用项目配色查看九宫格拉伸和文字安全区，并列出尚未导入的 UI 状态。

界面按原始像素展示，可横向滚动。这是平面排版预览，不模拟引擎字体、着色器、运行时缩放或真实交互。参考截图最长边有限，最终仍以游戏画面为准。

看完预览后，可以点「框选修改此版图片」直接回到这一版本的局部编辑。

「修正图标留白」会裁掉外部透明空白、保持主体比例、补足四边透明区域，生成一个待采用的新版本。原版本不变。像素画如需缩小会明确拒绝，避免模糊边缘。比例检查只提示保持比例显示，不会把模型或图片拉伸。

已有图片可以采用新版后撤销到前一版。首次导入没有前一版可恢复，撤销入口不会启用。预览、补留白、切换区域均不调用收费生成服务。

## 让资产符合玩法

在「这件资产怎么用」中保存资产 ID 和用途。后续设计与图片计划会保留这些要求：

| 用途 | 可以填写 | 实际处理 |
| --- | --- | --- |
| 道具 | 最小尺寸、缩放锁、预留空间 | 试放前检查；不满足时拒绝缩小或放置 |
| 门／宝箱 | 独立门板／箱盖 ID、转轴、开启角度 | 两个资产导入后，可安装已有交互组件 |
| 持握物品 | 命名挂点、本地位置和旋转 | 安装原生挂点，保留其他挂点和材质绑定 |
| UI | 文字安全区、需要的状态 | 写入生成要求，预览安全区与状态缺项 |

尺寸和预留空间使用引擎世界 XYZ、单位米；转轴和挂点使用引擎本地坐标。Unity 的 Y 向上，UE 的 Z 向上。预留空间是在包围盒两侧增加的范围，不是动态碰撞扫描。

门／箱盖必须是独立的已导入资产。现有交互模板的转动轴：Unity 门 `[0,1,0]`、箱盖 `[-1,0,0]`；UE 门 `[0,0,1]`、箱盖 `[0,1,0]`。界面选择用途时填写相应轴。其他轴要在引擎中自定义交互；不能把装饰性的铰链当成已经可用的玩法。

UI 状态按 `资产ID`（normal）、`资产ID_hover`、`资产ID_pressed` 等命名。缺项只是提醒，不会自动生成假状态或把缺失资源标成完成。原生交互与挂点安装后，需要在自己的游戏输入和角色尺寸下试用。

## 每个区域使用自己的美术要求

在「这个区域的美术要求」中保存区域名称、参考图、当前配色／材质设置和说明。可以分别固定轮廓、配色、比例、材质、细节。切换区域会清除旧的位置与相机选择，再读取当前位置，避免把药草店的尺寸拿到地牢里使用。

在画布采用预览后，会把结果保存为当前区域的采用样本；可先填写具体理由，也可随后保存「避免样本」。同一资产的选择保留版本。同一区域的后续创作会读取这些样本，其他区域的专用样本不混入；原有全项目样本仍通用。AI 需要实际查看图片后理解固定特征，不把文字规则当成外观已经合格的证明。

区域修改不重做旧作品。每次设计保留当时的区域版本、用途要求和场景依据。

## Codex／Harness 的操作

都通过 `game_workflow` 的 `describe`／`execute` 调用同一套接口：

| 动作 | 用途 |
| --- | --- |
| `reference_scene` → `task` → `save_scene_context` | 取得真实场景参考，最后传完成的 `inspection_id` 自动保留图片 |
| `asset_requirements` | 读取／保存一件资产的用途要求 |
| `preview_scene_model` | 传已导入资产和新的 `inspection_id`，返回持久预览任务及 `plan_id` |
| `preview_scene_image` | 传图片 ID、保留的 `revision`、显示尺寸和位置，生成平面预览 |
| `scene_preview_images` | 返回实际图像，宿主查看像素后再判断 |
| `scene_preview_action` | 对 `plan_id` 执行 `adopt`、`undo` 或 `discard` |
| `repair_image_padding` | 产生补留白的待采用图片版本 |
| `repair_scene_part`／`restore_scene_part` | 只改预览版本的指定部件，或恢复这次修改前的版本 |
| `apply_asset_requirements` | 安装已具备依赖的门／宝箱交互或持握挂点 |
| `save_scene_profile`／`activate_scene_profile` | 保存／使用区域美术要求，旧版本也可指定 |
| `remember_scene_example` | 为当前区域保存采用／避免结果及理由 |

宿主直接采用时，等待采用完成，再调用 `remember_scene_example`。失败、取消、项目切换或版本变化时，不能把未完成的结果记成采用。

原生临时 actor 接口参考：[UE EditorActorSubsystem](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/EditorActorSubsystem?application_version=5.7)。本次验证范围和限制见 [验证记录](verification-scene-studio.json)。
