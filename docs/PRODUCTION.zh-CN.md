# v0.10：从一句需求到项目中的可用资产

更新 [下载程序](https://github.com/316sandon12/prompt-to-scene/releases/latest)，在设置页重新连接项目并更新 Codex／Harness 插件；UE 更新桥接后重启一次。打开游戏项目，在 AI 客户端直接描述需求即可。已有项目和资产继续保留，不需要重新建立工程。

例如：

> 这是一个第一人称草药店经营游戏。参考项目里已有的木柜风格，做一张草药工作台和一个收纳架，放进刚才搭好的 shop 房间，留出行走与操作空间。用玩家摄像机检查材质和比例；只调整明显不协调的部分，完成后把这套设计保存下来。

AI 读取项目设定，选择已有设计、现有素材或专门建模。一个任务负责制作、材质准备、导入、布置和画面对照。用户无需手动转换格式、连接贴图或分别跟踪每个后台步骤。正常制作不强制增加候选挑选和确认环节。

## 六项功能怎样使用

| 功能 | 可以直接这样说 | 工具实际做什么 |
| --- | --- | --- |
| 从游戏画面改外观 | “从玩家视角检查这个柜子，木纹太抢眼，只降低木纹对比，保留造型。” | 保留同一摄像机、镜头和场景灯光；AI 查看真实图片，记录具体问题与偏好，最多两轮局部修复。 |
| 复用满意的设计 | “把这张桌子存成草药店系列，以后延续它的结构和材质。” | 保存有版本的 Blender 源文件、配方、命名部件和来源；新资产可改尺寸或局部部件，并沿用该系列方向。 |
| 发光、镂空与透明 | “做带发光标识、镂空叶片装饰和半透明盖板的容器，导入当前项目。” | 烘焙支持的程序化输入，处理透明度与发光贴图，在 Unity／UE 配置相应材质。 |
| 统一任务 | “做好这一组道具并导入，失败的地方接着完成。” | 一个父任务保存全部阶段和结果；恢复时复用成功步骤，避免重新生成整组模型。 |
| 让道具接入玩法 | “这个矿石采集三次后耗尽，换成碎石外观，触发 ore_mined 事件。” | 配置次数、距离、交互位置、标签、事件和耗尽模型；同时支持开关状态切换。 |
| 自动布置现有房间 | “用这些家具布置 shop 的第一个房间，保留门口和通道。” | 读取实际房间和模型尺寸，寻找位置并保留接近空间，原生净空检查失败时撤销布置。 |

## 不用记工具名

新安装的 Codex 和 Harness 插件默认只展示三个入口。AI 通过统一工作流按需发现并调用完整功能，原有命名整理、部件编辑、来源记录和撤销能力仍可使用。

本地创作台对应的位置：

- **视觉 → 查看角度 → 游戏摄像机**；打开完成的对照，再用“满意并记住偏好”记录方向。
- **素材库 → 把满意的模型存成可复用设计**；保存当前资产，查看已保存设计，制作同系列新资产。
- **玩法**：选择采集资源或开关，设置次数、事件名和标签。高级交互位置、耗尽资产可直接在聊天中描述。
- **关卡 → 把这个关卡布置成可用场景**：填写已有的关卡名称，选择资产和房间编号，自动布置。
- **任务与候选**：查看父任务进度，按需恢复或撤销布置。

本地窗口没有额外的聊天模型。自定义自然语言造型由 Codex／Harness 理解并生成建模脚本；窗口可以操作已有设计、内置道具和导入模型。可选生成服务仍然单独配置。

## 第一次用游戏摄像机

Unity 使用场景中标记为 **MainCamera** 的摄像机。UE 使用唯一的 CameraActor；有多个时，把希望使用的摄像机添加 Actor Tag **PTS.GameCamera**。工具复制镜头设置拍摄对照，不修改玩家摄像机。没有游戏摄像机时可以先选择模型展示角度。

画面对照和技术检查分别回答不同问题：图片用于判断比例、细节与材质是否协调；技术检查用于发现缺材质、悬空和可能穿插。成功导入不会自动被记为“外观满意”。配色识别、外观判断由当前 AI 客户端查看真实图片完成，不捆绑新的视觉模型。

## 把交互接到自己的游戏

Unity 生成可编辑 prefab；`Interaction.TryInteract(worldPosition)` 接收世界坐标米。每次成功交互都会触发 `onInteracted` 和带配置名称的 `onGameEvent(string)`；耗尽时另触发一次 `onDepleted`。资源耗尽后显示指定 prefab 的外观，未指定则隐藏资源。开关通过 `IsOpen` 读取状态。

UE 生成原生子 Blueprint；`TryInteract(WorldPosition)` 接收 UE 世界坐标厘米，每次交互触发 `OnInteracted`，耗尽时另触发 `OnDepleted`，可读取 `GameEventId`，资源可切换为指定 Static Mesh。交互配置中的位置仍统一使用米，插件负责转换。普通使用不需要 C++ 编译器。

库存加数量、任务进度和存档规则需要接入项目自己的逻辑。这次新增的是明确的事件入口，不能把填写事件名当成已经连接了整个背包系统。演示输入可关闭；试玩检查会实际进入 Play／PIE，完成后回到编辑模式。

## 当前边界

- 设计库保留可编辑来源和已有命名部件；单个融合网格不会自动被分解成正确的语义部件。现有素材匹配使用已观察的描述、标签、尺寸和面数，不是图像向量检索。
- 材质支持静态 PBR、发光、镂空和普通透明度。折射玻璃、混合着色器、骨骼动画和 HDRP 尚不支持，不承诺不同引擎灯光下像素一致。
- 自动布置针对本工具生成的现有房间，使用真实边界和采样净空；不自动推断任意平面图、替换建筑墙体或生成 NavMesh。
- 设计复用保留来源信息；商业素材的许可证由其原始授权决定，不能通过保存设计改为开放许可。
- 场景仍由你正常保存。恢复资产、撤销布置和撤销资源整理各有自己的范围。
