# 项目管家：少配置，直接在引擎里工作

v0.9 将项目规范、自动入库、引擎内工作台、素材识别和参考材质适配接入同一条流程。仍支持 Codex 与 DeepSeek Harness，也能使用本地创作台。

原生面板实拍：[Unity](images/project-workshop-unity.png) · [UE](images/project-workshop-unreal.png)。截图中的简单模型用于验证颜色、粗糙度和预览功能，不代表最终游戏美术效果。

## 升级后只做一次

1. 下载 [最新安装包](https://github.com/316sandon12/prompt-to-scene/releases/latest)，打开应用，对当前项目再点一次「连接并准备项目」。更新 AI 客户端插件并开启新会话。
2. Unity 等待编译后打开 **Tools → Prompt-to-Scene → Workshop**。UE 重启一次，打开 **Tools → Prompt-to-Scene Workshop**，或从内容浏览器右键打开。UE 提供真正的 Editor Utility Widget，用户不需要编译 C++。
3. 在本地创作台的 **项目管家** 中保存资源目录、命名、面数、贴图、LOD 和碰撞规范。Unity 面板也能保存常用设置；UE 的自动入库开关可直接保存默认规范。完整规则可用指令配置。

例如直接告诉当前 AI：

> 以后这个项目的模型用 SM_，材质用 M_，贴图用 T_，放进 GameAssets；道具控制在两万三角面、1024 贴图，保留两级 LOD。把它保存为项目规范。

规范保存在项目根目录的 `prompt-to-scene.json`，可以提交 Git。密钥保存在操作系统凭据库，不进入项目。新管理资产位于「资源目录 / PromptToScene / 资产编号 / 类型目录」；已有资产保持原路径，修改规范不会隐式搬动旧资产。生成的内部文件保留稳定身份；同一个源文件的后续修订更新同一资产。

## 把文件放进收件箱

默认收件箱是项目根目录的 `AssetInbox`，位于 Unity 的 Assets 或 UE 的 Content **之外**。可以改成另一个项目内源文件目录。将 GLB、glTF、FBX 或 BLEND 和依赖文件放进去，勾选「自动入库」。

应用、AI 连接或引擎至少有一个保持打开时，会等待文件复制稳定，再自动准备 PBR 材质、面数、贴图、LOD 和碰撞，导入原生预制体或静态网格。原文件保留。模型外部贴图和 glTF 缓冲区变化也会被检测；每个模型最好放进自己的子目录。

同一版本不会重复导入。文件改变后会生成新修订；失败项显示原因，可点「重试此项」。关闭所有应用和编辑器后没有系统常驻监控服务。一次收件箱扫描最多 200 个模型，单模型最多 256 MiB、依赖包最多 512 MiB。`.gltf` 的相对依赖必须留在收件箱内。

> 把收件箱里新来的模型全部按当前项目规范入库，完成后告诉我哪些成功、哪些需要处理。

## 选中资源就能整理

Unity 的 Project 右键菜单提供「Organize selection」「Inspect selection」；UE 内容浏览器右键可打开原生工作台。操作默认使用当前项目和选择。整理先显示原路径与目标路径，再应用；记录保存在项目内，可撤销。检查会列出模型尺寸、三角面数以及超出项目预算的项目。

「从现有项目建议前缀」读取真实资源清单，展示每种前缀的数量和占比。它提供建议，选择采用后才写入规范。扫描被截断时会要求缩小范围。特殊加载目录、代码与插件管理资产仍受保护；自定义字符串路径加载的资源应加入排除规则。[完整整理说明](ORGANIZATION.zh-CN.md)。

## 让 AI 看见素材，再命名和检索

在项目管家搜索并勾选模型，点击「捕获素材缩略图」。结果包含引擎实际渲染的图片、尺寸、三角面和材质标签。告诉当前 AI：

> 看看刚捕获的素材图，给它们建议名称、材质、风格和适合的用途。拿不准的地方标低置信度，先不要改动文件名。

AI 读取图像证据后保存结构化描述。你也能直接修改描述，点击「保存我的识别与纠正」；自动识别不会覆盖人工纠正。搜索会使用这些描述和标签，例如「适合酒馆的旧木椅」。这属于视觉描述加关键词检索，不是向量相似度搜索。

按建议名称整理时，先生成限定所选资源的移动方案。插件管理的生成资产保持受保护状态，仍可按描述检索。原生类型分类覆盖多种资源；视觉捕获目前针对可渲染的模型、预制体和兼容的静态 Blueprint，不宣称能识别任意脚本、动画或音频内容。

如需独立批量识别，可配置支持图片输入的 OpenAI 兼容 `/chat/completions` 接口。地址填到 API 根目录，例如 `http://localhost:1234/v1`。调用远程服务前需要允许发送本次缩略图和资产元数据；可能产生的服务用量由所配置的服务决定。无需此服务也能让当前聊天 AI 读取图片。

## 把一套素材的外观靠近参考

1. 勾选目标资产：Unity 使用 `.prefab`，UE 使用 `StaticMesh`。原始 FBX 可选择入库后生成的预制体；当前不直接改 Unity 模型导入器或 UE Blueprint 的整套材质。
2. 选择项目内的参考模型或材质，勾选颜色、粗糙度、贴图缩放。
3. 生成预览，查看真实前后图和支持情况，勾选材质槽后应用。Unity 原生面板提供勾选；UE 可输入材质行编号，例如 `0, 2`，留空表示全部。

目标几何与原贴图保持不变。Unity 创建独立材质，UE 创建材质实例；预览副本与原资产分开保存在 `PromptToScene/Adaptation`。撤销会恢复原始材质引用；如果用户已经另行更换材质，会停止并提示冲突。

参考模型使用第一份可用材质。Unity 识别 Standard/URP 等常见颜色、光滑度和贴图属性；由打包贴图控制的粗糙度会跳过。UE 识别 `PTS_Color / PTS_Roughness / PTS_UVScale` 及常见同义参数；自定义着色器未暴露这些参数时会跳过，并显示原因。它不会把任意 Shader 或参考图片自动变成相同效果。已有参考图片与美术方向仍使用原有视觉检查流程。

## 已验证的范围

原生联调环境是 macOS、Blender 4.2、Unity 2022.3.62f3c1 与 UE 5.7.2。UE 面板模板由 5.7.2 保存，旧版 UE 可能无法读取；不将其描述为全版本兼容。Windows 安装包与服务协议由便携测试验证，Windows 原生编辑器的完整联调仍需独立验证。详细测试结果见 [verification](verification.md)。
